# AAB-001 — 24–48 Hour MVP Delivery Priority

Owner directive: Deliver a usable EARLY-STAGE autonomous programming workflow within approximately 1–2 days, not a polished final product. Prioritize something working and extensible over more procedural gates, isolated function demos, investigations or theoretical architecture. Treat this as the current delivery priority for AAB-001, subject to explicit later owner revision.

## Minimum viable outcome
From an Android phone, owner grants ONE narrow approval for ONE well-defined small software project to Grok (through its existing chat) and does not manually relay intermediate code/files or approve each micro-step.
Grok automatically decomposes the preapproved project, dispatches existing workers/routines (no new paid services), writes a COMPLETE usable small application, tests and repairs it within a bounded scope, and preserves complete source and checkpoints in private GitHub on mc/channel / draft PR #2 or another explicitly approved existing branch. Success means an actual runnable app/CLI with clear invocation, observable output, error handling, tests and one evidence handoff—not merely another standalone controller function.
ChatGPT independently retrieves and reviews the complete result. For the 48-hour MVP, owner invoking ChatGPT to check the final handoff is ACCEPTABLE; fully autonomous ChatGPT return triggering is a stretch goal and must NOT block the first working product. Do not claim permanent unattended two-way autonomy until an actual wake-to-review-and-return has been independently observed.

## Delivery sequence
1. One concise bounded whole-application goal and acceptance criteria, selected by architect/owner, using synthetic data only. Choose an actual useful AAB tool/working CLI with a straightforward way to invoke it on Grok's test environment and inspect source from Android.
2. One direct owner authorization to Grok for the whole scope, including automatic subtasks/fixes/checkpoints. Existing Grok PR event watch to be armed reversibly for this exact scope; do not broaden permissions for other GitHub comments.
3. Execute through preapproved Grok workers/routines. Preserve working application source, run command, sample output, tests and evidence in GitHub. No intermediate owner relay.
4. ChatGPT independently checks output and tests and records release-gate result. Accept a single user "Check GitHub" prompt as MVP fallback if ChatGPT automatic wake review is still broken.
5. Only after this usable early version is proven, tackle stronger durable task ledger/CAS, enforceable permissions/isolated machines, richer agent orchestration, automatic ChatGPT reviewing, Android packaging/UI and crash/concurrency recovery.
